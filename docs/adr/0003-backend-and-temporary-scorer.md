# ADR-0003: реализация бэкенда и временный скорер

Дата: 20.10.2026. Статус: принято по запросу пользователя.

Реализуется бэкенд согласно ADR-0001/0002. Фронтенд пользователь отложил. MVC-контроллеры передают данные в model и возвращают имена будущих представлений; `DeferredViews` возвращает явный 501. Thymeleaf, HTMX, Bootstrap, формы кабинета и дизайн пока не добавляются. Встроенная login-форма Spring Security и Swagger — технические средства проверки. POST-команды работают: form-urlencoded/multipart, session + CSRF, 303 или HX-Redirect. JSON-дублей клиентских команд нет.

Вместо правил score_v1 временно используется `AlwaysRejectScorer` за `RiskScorer`: provider `rules`, model_version `stub_reject_v1`, score 105, HIGH, stop flag `SCORER_ALWAYS_REJECT`. Это явная заглушка по требованию пользователя, а не модель риска или политика банка. Ни одна реальная заявка не может получить предложение через этот скорер. Некорректные/неполные сведения по-прежнему ведут в NEEDS_INFO; технические сбои — в processing_state FAILED. Только готовый результат приводит к кредитному отказу.

Credit-worker сохраняет самостоятельную политику decision_v1 и ветки offer/contract/ledger. Положительные ветки проверяются тестовыми assessment-результатами без изменения рабочего провайдера. Для будущей замены скорера потребуется новая модель/версия и request_id; сохранённые оценки не перезаписываются.

Уточнение реализации: задачи db-scheduler используют CustomTask с CompletionHandler для ограниченного backoff, а доменная job хранит attempts/diagnostics. Это не вторая очередь и не собственный polling. Все изменения домена и постановка следующего задания выполняются одной транзакцией через TransactionAwareDataSourceProxy. Тест проверяет совпадение PostgreSQL connection backend PID, commit и rollback JPA/JDBC/очереди.

Процесс workers запускается тем же JAR с профилем worker; API-процесс без этого профиля не исполняет задания. Схемы core/auth доступны роли credit; схема assessment — отдельной роли assessment. Flyway работает от роли своего сервиса. Изоляция runtime/migration credentials внутри одного сервиса может быть добавлена отдельно.
