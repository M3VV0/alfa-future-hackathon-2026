# Датасет для Scorer

[`synthetic_credit_users.csv`](../synthetic_credit_users.csv): 10 000 заявок, 32 входных поля из [INTERFACE.md](INTERFACE.md) и `target`. Названия колонок и ключи JSON — на английском. Кодировка UTF-8 с BOM, разделитель — запятая. Даты состояния бизнеса сохранены: срез 10.10.2026. Изменение набора выполнено 21.10.2026.

`target` — **синтетическая расчётная годовая ставка в процентах**, которую можно использовать для демонстрационного решения. Значение есть и для отказных сценариев: оно не означает, что такой кредит был одобрен или выдан. Это не вероятность дефолта и не полная стоимость кредита.

## Распределение

Диапазон 40–70% из задания интерпретирован как доля строк с аномально высокой ставкой; выбрано 55%.

| Группа | Строк | Доля | Получившиеся ставки, % годовых |
| --- | ---: | ---: | ---: |
| Низкие | 1 500 | 15% | 7,16–10,85 |
| Обычные | 3 000 | 30% | 12,01–34,97 |
| Высокие | 5 500 | 55% | 35,06–69,99 |

Для демонстрации можно считать `target < 12` и `target >= 35` основанием для `DECLINED`; внутри диапазона `[12, 25)` — `OK`, `[25, 35)` — `OFFER`. Нижняя граница означает ценовое ограничение продукта: слишком низкая ставка не свидетельствует о неплатёжеспособности клиента. Эти границы придуманы для сценариев прототипа; реальные решения потребуют дополнительных данных и правил. Реализованный [Scorer](../scorer.py) прогнозирует ставку обученной моделью, а демонстрационные пороги не входят в его логику.

В CSV не добавлены группа, решение или промежуточные признаки, раскрывающие ответ. Группы перемешаны по `id` и не совпадают с последовательными блоками строк. Доли намеренно изменены для тренировки и проверки модели: это не оценка частот реальных отказов или рыночных ставок.

## Как согласованы заявки и ставки

Далее приведено историческое описание генерации. Генератор, исходная версия CSV и построчный аудит отсутствуют: сохранность прежней маски пропусков, происхождение каждой строки и точные числа отдельных сценариев нельзя независимо подтвердить по текущей поставке. Размер, диапазоны, распределение групп и графиков платежей проверяются по доступному CSV.

По историческому описанию использована существующая выборка, сейчас расположенная в `code/scorer`. Сохранены субъекты, их правовая история, категории МСП, все цели кредита, оба типа заявителя, оба графика платежей и существующие пропуски. По заданию изменены сумма, срок, стоимость обеспечения и `target`.

Сценарии высоких ставок:

- **1 798 чрезмерных сумм:** нагрузка на условный бюджет обслуживания долга значительно выше нормальной.
- **1 843 сжатых графика:** погашение за 6–18 месяцев создаёт высокие годовые платежи.
- **1 859 случаев слабого обеспечения:** обеспечение покрывает только небольшую часть кредита, а долговая нагрузка уже повышена.

В низкой группе — небольшая относительно масштаба бизнеса заявка, обеспечение примерно в 2–3 раза выше суммы и регистрация не позднее 2021 года. Это сильные бизнесы с низкой расчётной ценой, которая может оказаться ниже нижней границы демонстрационного продукта. В обычной группе нагрузка и обеспечение принимают промежуточные значения.

Суммы находятся в пределах **100 тыс. — 588,26 млн рублей**. Только стрессовые сценарии могут превышать прежний предел 150 млн; таких строк 282. Это запрошенная сумма по потенциально отказной заявке, а не подтверждённый лимит кредитования МСП. Сроки — 6–120 месяцев. График платежей сохранён: 9 793 ежемесячных и 207 квартальных.

Реальной выручки, денежного потока и обязательств в интерфейсе нет. Поэтому генератор использует явно условный **бюджет годового обслуживания долга**:

```text
employees_proxy = average_headcount, если численность заполнена;
                  иначе 5 / 40 / 150 для micro / small / medium
annual_debt_budget = 250000 + 450000 * employees_proxy
reference_debt_load = приведённая к году аннуитетная нагрузка при 20% / annual_debt_budget
```

Подстановка численности используется только в сценарном расчёте и не заполняет пропуски в исходном поле. Этот бюджет **не является доходом, выручкой, лимитом банка или показателем DSCR**. Базовые 20% — фиксированное допущение для сравнения графиков, а не текущая рыночная ставка. Аннуитет рассчитан с соответствующей месячной/квартальной периодичностью. Приведение к году — платёж × 12 или × 4; для кредита короче года это показатель интенсивности платежей, а не сумма фактических выплат за первый год.

## Формула target

Эта формула описывает допущения генерации данных, а не реализованное решение: текущий `Scorer` применяет обученный CatBoost. Формула и её заранее заданные коэффициенты не используются при подготовке признаков, обучении или прогнозе; для реальных данных потребуется переобучение.

Во всех трёх группах используется одна формула. Сначала выбирается целевая группа сценария, затем подбираются параметры заявки, для которых формула даёт ставку внутри соответствующего диапазона. Сам идентификатор группы в формулу не входит.

```text
coverage = declared_collateral_value / requested_amount

target = round(
    15
    + 28 * max(0, reference_debt_load - 0.30)
    + collateral_premium - collateral_discount
    + age_premium + term_premium + frequency_premium
    + product_margin + noise,
    2
)

collateral_premium = 6 * max(0, 1 - coverage)
collateral_discount = 7 * min(coverage, 2) / 2
При неизвестном залоге: collateral_premium = 7, collateral_discount = 0

age_premium = max(0, 5 - years_since_registration) * 0.6
term_premium = max(0, term_months - 36) / 12 * 0.15
frequency_premium = 0.35 при quarterly, иначе 0
noise ~ Normal(0, 0.5)
```

Год регистрации извлекается из ОГРН/ОГРНИП; возраст считается приблизительно, по разнице годов со срезом. Надбавки по цели: `commercial_mortgage=0.2`, `business_auto=0.5`, `equipment=0.7`, `refinancing=0.8`, `investment=1.0`, `working_capital=1.2`. Все коэффициенты — авторские допущения симулятора.

Увеличение суммы при остальных равных не уменьшает расчётную ставку; увеличение обеспечения не повышает её. В высокой группе нагрузка на условный бюджет выше 1, а обеспечение не превышает примерно 1,2 суммы. В низкой группе нагрузка ниже 0,3 и обеспечение не ниже примерно двух сумм кредита. Пол, гражданство, ФИО, социальный статус, ИНН, уникальная часть ОГРН и происхождение из XML в расчёте не используются.

## Схема, пропуски и источники

Поля даты рождения, повторных ИНН, признака совпадения ИНН, лицензий и кода способа образования отсутствуют. `formation_method_name` сохранён. В CSV находится сокращённая схема scorer, а [DETAILED_MODEL_INTERFACE.md](DETAILED_MODEL_INTERFACE.md) описывает более широкий набор возможных входных данных; его исключения согласованы с запросом.

Исправлены ошибки числового преобразования реквизитов: убраны `.0` у ОГРН/ОГРНИП/КПП, восстановлен трёхзначный код страны, например `051`. Сами номера не заменены. Численность приведена к целочисленной записи. При чтении pandas используйте `dtype=str, keep_default_na=False, skipinitialspace=True`, затем удалите внешние пробелы заголовков и строковых значений и явно преобразуйте числовые поля. В текущем CSV есть пробелы перед кавычками JSON: без `skipinitialspace=True` поля смещаются в составной индекс; проверяйте обычный `RangeIndex` и точную схему из 33 колонок.

**Новых пропусков не добавлено, существующая маска пустых ячеек полностью сохранена.** Структурные `null`, например поля физлица у ООО, не считаются искусственным повреждением. Сохраняется многочисленное представление прежних небольших категориальных признаков; для каждого проверяемого значения — минимум 50 строк. JSON не повреждались.

Новые компании из внешних источников или XML не копировались. Взяты уже существующие 10 000 синтетических субъектов; первоначальная генерация использовала 5% сценариев по обобщениям XML. Исходного XML и старого аудита в текущей структуре проекта уже нет, поэтому эта историческая доля здесь не перепроверяется. Текущая переработка не использует XML.

Проверенные структурные ориентиры прежней генерации: [классификаторы Росстата](https://www.rosstat.gov.ru/classification), [описание реестра МСП ФНС](https://www.nalog.gov.ru/rn77/related_activities/regbusiness/reestrquetoin/), [ИНН ФНС](https://www.nalog.gov.ru/rn77/fl/interest/inn/). Новое распределение ставок, бюджет обслуживания и формула — сценарные правила, **не данные этих источников**. Утверждений о реальных индивидуальных банковских одобрениях или отказах они не дают.
