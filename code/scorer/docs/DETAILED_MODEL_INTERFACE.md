# Данные для модели: состав источников и предлагаемая типизация

Проверено 20.10.2026 по исходному перечню полей; его нумерация сохранена ниже. Текущий сокращённый контракт описан в [INTERFACE.md](INTERFACE.md). По уточнению пользователя исключены пункты 9, 12, 13, 25 и 35; поле кода способа образования также исключено; из полей ИНН оставлено только поле заявки, включая удаление ИНН из вложенных структур. Для пунктов с источником «заявка» внешняя проверка не выполнялась, как и было запрошено. У пункта 4 источник не указан: ниже он **предположительно отнесён к заявке**, без приписывания этих данных ведомству.

В первой колонке — сведения, подтверждённые описаниями форматов и опубликованными документами; во второй — **предложение для проекта**, а не готовая схема ФНС и не доказательство полезности признака для скоринга. ЕГРИП, ЕГРЮЛ и реестр МСП ведёт ФНС. СФР и лицензирующие органы передают соответствующие сведения, которые ФНС отражает в реестрах.

Подтверждение поля в формате означает, что источник способен его передавать. Оно не гарантирует заполнение поля у каждого предпринимателя, полноту истории или доступность закрытых сведений.

## Как читать типы

- `string`, `date`, `bool`, `int`, `decimal(p,s)` — предлагаемые типы хранения; `?` означает возможность `null`. Даты нормализуются в `YYYY-MM-DD`, исходное представление сохраняется.
- `enum` — категория, а не число с арифметическим смыслом. `list<struct{…}>` — повторяющиеся записи, которые удобнее хранить в дочерней таблице.
- ИНН, ОГРН, ОГРНИП, КПП, регистрационные номера и коды классификаторов сохраняются строками. Их нельзя превращать в непрерывные числовые признаки.
- Для каждого поля или блока предлагается хранить `availability: enum{present, not_in_response, restricted, not_applicable, fetch_error, parse_error}`. `restricted` ставится по подтверждённому ограничению; причина пропуска не угадывается. Пустой список означает отсутствие записей в успешно прочитанном блоке, а не доказанное отсутствие факта в реальном мире.
- В ML передаются преобразованные признаки. Исходные документы, идентификаторы и служебные поля сохраняются отдельно для сопоставления и проверки.

После сопоставления использовать единый набор признаков, не дублировать одни и те же коды дважды. Процентных долей в проверенной структуре МСП нет. |

Возможный категориальный признак. Отсутствие ответа источника не равно `false`; положительный статус сам по себе не доказывает меньший кредитный риск. |
| **37. Продукция и инновационность/высокотехнологичность.** Необязательный список `СвПрод`: код ОКПД2, наименование и **один общий** признак `ПрОтнПрод` (`1` — инновационная/высокотехнологичная, `2` — нет). Данные вносятся добровольно. [Формат МСП, табл. 4.8][MSP-FORMAT], [ФНС: вопросы и ответы][MSP-QA] | `products: list<struct{okpd2_code: string, name: string, innovative_or_hightech: bool}>?`. Для ML — группы продукции, число раскрытых позиций, наличие положительного общего признака. Отдельные флаги «инновационная» и «высокотехнологичная» по этому полю восстановить нельзя. Пропуск блока не доказывает отсутствие производства или инновационной продукции. |
| **38. Участие в программах партнёрства по 223-ФЗ.** Необязательный список `СвПрогПарт`: ИНН заказчика и дата договора присоединения; необязательные наименование заказчика и номер договора. Представление сведений добровольное. [Формат МСП, табл. 4.9][MSP-FORMAT], [ФНС: вопросы и ответы][MSP-QA] | `partnerships: list<struct{customer_name: string?, agreement_number: string?, agreement_date: date}>?`. Для ML — число раскрытых записей и время с договора на дату заявки. Без ИНН нельзя надёжно определять число уникальных заказчиков. Это договор присоединения к программе: суммы поставок, выручка и исполнение закупочных контрактов в этом блоке **отсутствуют**. |

## Общие структуры — предложение для реализации

`Activity`:

```text
{
  code: string?,
  name: string?,
  classifier_version: string?,
  evidence_type: enum{declared,reported,unknown},
  role: enum{primary,additional,unknown},
  source_registry: enum{egrip,egrul,msp},
  snapshot_on: date?
}
```

`LegalEntityRef` для п. 20/22:

```text
{
  ogrn: string?,
  name: string?,
  availability: enum
}
```

Необязательность в проектной структуре нужна в том числе для старых, ограниченных и частично распознанных документов. Она не отменяет обязательность реквизитов в конкретной версии формата ФНС: это отдельная проверка качества входного документа.

## Проверка достоверности и границы результата

Первоначальная проверка проведена по исходному перечню; текущая схема учитывает перечисленные выше исключения: **1–7** оставлены как данные заявки без исследования внешнего источника; **8–26** сопоставлены с содержанием ЕГРИП/ЕГРЮЛ; **27–38** — с официальной схемой и описанием выгрузки МСП. Для каждого ведомственного пункта дана ссылка и, где применимо, номер таблицы формата. Описания первичных документов ФНС прочитаны в правовой базе; их происхождение и редакции сверены с карточками приказов на сайте ФНС. Разбор XSD и DOCX реестра МСП выполнен по файлам с домена `file.nalog.ru`.

Выявленные ограничения отражены непосредственно в строках:

- **Данных нет в выбранном открытом канале:** полный адрес из блока МСП, процентные доли ОКВЭД в публичных сведениях, два отдельных признака инновационности/высокотехнологичности, финансовые результаты партнёрских программ. Отсутствие этих полей не означает, что они не существуют в других источниках.
- **Формат допускает данные, но заполнение не гарантировано:** связи правопреемства, раскрываемые сведения об участниках и представителях, продукция и партнёрство. Долю заполненных записей в реальной генеральной совокупности эта работа не устанавливает.
- **Сведения требуют интерпретации:** дата включения в МСП не является возрастом бизнеса; уставный капитал не является остатком средств; закрытие бизнеса, ликвидация и банкротство не взаимозаменяемы.
- **Не приписывается источнику:** имена полей на английском, внутренние `enum`, агрегаты, логарифмы, отношения величин и рекомендации об исключении признаков — проектные предложения.

Проверка основана на опубликованных структурах и примере выписки, а не на массовой проверке всех записей реестров. Подлинность электронной подписи опубликованного PDF отдельно не проверялась: он использован как пример расположения и содержания полей. Ссылки на старые новости ФНС использованы для подтверждения смысла сведений, а не как спецификация текущего XML.

## Условия подготовки обучающей выборки

Это предложения по использованию перечисленных данных:

1. **Зафиксировать момент прогнозирования.** Для каждой заявки хранить `application_at`, а для источника — `snapshot_on`, `retrieved_at`, `source_url`, `schema_version`, хеш документа. Дату самого события и дату его регистрации хранить раздельно. При ретроспективном обучении брать только информацию, доступную к моменту заявки: сегодняшняя выписка с историческими датами сама по себе этого не гарантирует.
2. **Различать пропуски.** Не смешивать отсутствие субъекта в реестре, отсутствие поля, неприменимость, ограничение доступа, сетевую ошибку и ошибку парсинга. Флаги технических ошибок по умолчанию использовать для контроля качества и маршрутизации, а не как характеристику заёмщика.
3. **Устранить дубли.** ОКВЭД повторяются в нескольких пунктах. Сохранять происхождение значений, выявлять конфликты и выбирать значение по дате и заранее определённому приоритету источника. Не создавать искусственный вес за счёт повторения признака.
4. **Разделить хранение и модель.** Сохранять реквизиты и исходный текст для аудита; передавать в модель проверенные категории, числа и временные интервалы. Кодировщики категорий, заполнение пропусков и масштабирование обучать только на тренировочной части. Разделять выборку по времени и заёмщику, чтобы одна компания не попадала в обучение и проверку через разные заявки.
5. **Различать ставку и вероятность дефолта.** Текущая модель обучена на синтетическом `target` — годовой ставке, и возвращает её как float; см. [контракт](INTERFACE.md) и [эксперимент](EXPERIMENT.md). Перечисленные реестры не дают здесь размеченную историю погашения кредита. Для модели вероятности дефолта нужны определение события, горизонт наблюдения и история обязательств/платежей. Факт закрытия ИП или отказа банка нельзя без обоснования объявлять кредитным дефолтом.
6. **Для хакатона использовать синтетические записи и локальные адаптеры.** Это следует из [requirements.md](../../../requirements.md). Публичная электронная выписка о конкретном лице доступна бесплатно, но массовая интеграционная выгрузка ЕГРЮЛ/ЕГРИП для ЮЛ/физлиц описана ФНС как платная услуга. Поэтому опубликованную спецификацию можно использовать для проектирования моков, не закладывая платную интеграцию в запуск прототипа. [ФНС: электронные выписки][EXTRACT-CONTENT], [ФНС: порядок доступа][ACCESS]
