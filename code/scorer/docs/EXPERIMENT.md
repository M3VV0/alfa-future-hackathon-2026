# Эксперимент регрессии ставки

[scorer.ipynb](../scorer.ipynb) содержит выполненный эксперимент, русские объяснения решений, графики и итоговые метрики. Результат — обученная модель регрессии ставки с самостоятельным применением через `Scorer`; синтетические данные служат допущением прототипа, а качество на реальных наблюдениях пока не проверено.

## Запуск

Из корня репозитория, в окружении Python 3.13.7:

```bash
uv pip install --python .venv/bin/python -r code/scorer/requirements.txt
```

Откройте `scorer.ipynb`, выберите ядро `.venv/bin/python` и выполните **Run All**. После выполнения обновите итоговую Markdown-ячейку по полученным метрикам и сохраните ноутбук с выводами.

Заключение — обычный статический Markdown: оно не меняется автоматически и при прерванном запуске может относиться к предыдущему эксперименту.

Рабочая директория ядра может быть корнем репозитория или `code/scorer`; установка пакетов внутри ноутбука не выполняется. Все импорты находятся в первой кодовой ячейке, остальные ячейки разделены по логическим действиям и начинаются с однострочного русского комментария.

Обучение последовательное, с двумя потоками; бюджет 600 секунд проверяется между fit, а новые попытки поиска прекращаются после 420 секунд с резервом для финальной проверки. Это мягкий лимит, который может быть превышен длительностью одного fit. Параметр CatBoost `used_ram_limit` ограничивает только расчёт CTR, поэтому фактический пик памяти записывается отдельно.

## Протокол и артефакты

Текущий результат — CatBoost `anchor_engineered` с 19 признаками набора `engineered`: 1000 деревьев, depth 6, learning_rate 0,05, l2_leaf_reg 3, random_strength 1, rsm 1. Проверены семь наборов признаков и 25 конфигураций; продукция, партнёрства и демография участвовали в сравнении, но в выбранные 19 признаков не вошли.

Сохранённая CV на 7000 fit дала OOF RMSE 1,1116 п.п. На повторном диагностическом holdout из 2000 строк RMSE составляет 1,0145 п.п., MAE — 0,6416 п.п., R² — 0,99731; ориентир RMSE ≤ 1 не достигнут. Квартальный сегмент слабее: RMSE 2,9492 п.п. на 46 строках. Обучение, поиск и CV в сохранённом запуске заняли 51,9 с до holdout/bootstrap, пик RSS — 558,4 МиБ; это не измерения полного Run All или задержки predict.

Прежние 2000 holdout-строк сохраняются, а из прежних 8000 development выделяются 7000 fit и 1000 hypothesis-validation, то есть 10% всей выборки. Все заёмщики уникальны; все эти данные уже использовались раньше, поэтому новое разделение не создаёт независимого теста.

Семь наборов признаков сравниваются на одинаковых 7000/1000 строках и параметрах CatBoost. Среди результатов в пределах 0,02 п.п. от минимального validation RMSE выбирается меньший набор; в него входят только группы, полезность которых поддержана этим ограниченным сравнением.

Для выбранного набора заранее создаётся план из 24 случайных конфигураций и одного контроля: глубина 4–8, learning rate 0,025–0,12 и L2 1–30 по логарифмической шкале, 800/1000/1400/1800 деревьев, random strength 0 или 0,01–3 и rsm 0,7–1. Результаты и статусы `completed`, `skipped_budget` или `failed` записываются во временный CSV; в выводах ноутбука остаются десять лучших завершённых конфигураций и число попыток каждого статуса. После анализа CSV удаляется; ранняя остановка по оцениваемой выборке не используется.

Три лучших завершённых конфигурации, прежний инженерный контроль и Ridge проходят одинаковую трёхблочную CV только на 7000 fit, без validation-тысячи. Выбранная модель затем обучается на всех 8000 development. CV после отбора и прежний просмотренный holdout используются как описательная диагностика, а не независимое подтверждение качества всей процедуры поиска.

Финальный выбор среди обученных Ridge и CatBoost основан на pooled OOF RMSE с предпочтением простоты в пределах 0,02 п.п. от минимума: сначала Ridge, затем меньшее `iterations × 2^depth`, затем меньшее число признаков. Средний прогноз служит только baseline; готовая формула, её компоненты, фиксированная ставка, денежный бюджет по численности, надбавки по продуктам и подстановки работников по категории МСП исключены из выбора и применения.

Общие преобразования [features.py](../features.py) формируют до 46 признаков: параметры заявки, финансовые отношения, реестровые сведения, продукцию, партнёрства и демографические категории. Пол, страна и гражданство сохраняются в данных и проверяются отдельной гипотезой и абляцией полного набора; решение о включении основано на validation, а не на исключении этих полей заранее.

JSON-строки и типизированные словари/списки обрабатываются одинаково; неизвестный блок отличается от пустого списка. Будущие вложенные события и договоры исключаются относительно среза, а даты МСП позже среза и незавершённый отчётный год отклоняются. Проверка отчётного года не предполагает календарь публикации: фактическая доступность источника без времени получения не доказана.

В `code/scorer/artifacts/` после успешного выполнения остаётся только `selected_model.joblib`: обученный estimator, спецификация, схема, версия и хеш кода признаков. Для анализа ноутбук временно записывает:

- `split.csv` — роли 7000/1000/2000 строк и CV-блоки только fit;
- `feature_hypotheses.csv`, `search_results.csv` — измеренные эффекты семи наборов и все попытки расширенного поиска;
- `cv_folds.csv`, `cv_results.csv`, `oof_predictions.csv` — CV финалистов и их прогнозы на 7000 fit;
- `holdout_intervals.csv`, `holdout_slices.csv`, `holdout_predictions.csv` — диагностика и 95% bootstrap-интервалы;
- `learning_curve.csv` — пять размеров обучения выбранного регрессора.

Последняя кодовая ячейка сохраняет сводку запуска (параметры, версии, метрики и хеши) в JSON-выводе самого ноутбука и удаляет перечисленные CSV, прежний `experiment_manifest.json` и устаревшие `selected_ml.joblib`, `best_catboost.cbm`, `selection.json`, `holdout_metrics.csv`. Очистка выполняется после анализа и проверки прогнозов при Run All; неизвестные файлы не затрагиваются. При ошибке до завершения временные файлы могут остаться для диагностики.

Таблицы анализа, графики и сводка запуска остаются в выводах ячеек и доступны для написания заключения. Построчные CSV после завершения не сохраняются; для их повторного расчёта нужен запуск эксперимента.

## Для чего используются хеши

SHA-256 входного CSV фиксирует точные входные байты, хеш кодовых ячеек — исполняемую версию эксперимента. Хеш модели позволяет проверить сохранённый файл; хеши временных таблиц фиксируют их состояние перед удалением и позволяют сравнить повторно рассчитанные результаты. Markdown и выводы ячеек не входят в хеш кода, поэтому обновление статического заключения не меняет идентичность вычисления.

Хеш и версия `features.py` внутри модели защищают от несовпадения обработки при обучении и применении. Это консервативная проверка: изменение даже комментария требует нового экспорта, а совпадение хешей не является подписью автора, доказательством корректности или отсутствия утечки.

Сводка различает полный обучающий запуск и целевую проверку сохранённой модели. При сверке 23.10.2026 повторно рассчитаны прогнозы и метрики holdout без обучения; результаты поиска, CV и ресурсные показатели сохранены из прежних выводов ноутбука. Хеш текущего кода не является доказательством полного повторного выполнения; следующий Run All сформирует новую сводку всего эксперимента.

## Применение и проверка

`Scorer` из [scorer.py](../scorer.py) в конструкторе создаёт готовый pipeline из выбранного обученного estimator и общей предобработки, загружая `artifacts/selected_model.joblib` относительно собственного файла. Он применяет те же `make_features` и `model_input`, что и ноутбук, проверяя версию и хеш кода; при изменении преобразований необходимо переобучить и экспортировать модель.

Из `code/scorer`:

```python
import asyncio

from scorer import Scorer

model = Scorer()
rate = asyncio.run(model.predict({
    "requested_amount": 1000000,
    "term_months": 24,
    "currency": "RUB",
    "payment_frequency": "monthly",
    "financing_purpose": "equipment",
    "msp_category": "micro",
    "applicant_entity_type": "legal_entity",
    "snapshot_on": "2026-10-10",
    "average_headcount": 10,
    "declared_collateral_value": 800000,
}))
```

В уже работающей асинхронной функции или Jupyter вызывайте `rate = await model.predict(row)` вместо `asyncio.run`. Метод принимает только одну запись — словарь/Mapping или `pandas.Series` — без `target` и возвращает `float` в процентах годовых; поле `target`, DataFrame и списки записей отклоняются.

Предобработка и прогноз выполняются через `asyncio.to_thread`, поэтому не блокируют event loop; вызовы одного экземпляра защищены блокировкой в рабочем потоке, а CatBoost использует два потока. Необязательные численность, залог и регистрационные номера могут отсутствовать; неизвестные величины не заменяются нулём, а ошибки проверки входа передаются через `await`.

Из корня репозитория:

```bash
.venv/bin/python -m unittest discover -s code/scorer/tests -v
.venv/bin/ruff check --select I001 code/scorer
```

Тесты проверяют загрузку без состояния ноутбука, одиночные и конкурентные асинхронные прогнозы, отсутствие блокировки event loop, отклонение target и пакетов, независимость от идентификаторов, пропуски и нули, новые категории, JSON-эквивалентность, даты, некорректные входы и несовместимый код признаков. Исходный CSV не изменяется, а решение по порогам ставки остаётся вне `Scorer`.

## Ограничения

Один срез 10.10.2026 не позволяет провести временную валидацию, а отсутствие `application_at` не позволяет доказать доступность исторических сведений на момент заявки. Bootstrap-интервалы условны относительно фиксированной модели и текущей смеси синтетических сценариев; они не учитывают повторное обучение и не являются индивидуальными интервалами прогноза.

Связи компаний и близкие дубликаты полностью не исследованы. Использование демографии и групповые метрики на синтетических данных не устанавливают справедливость или пригодность модели для реальных кредитных решений.

В текущей поставке отсутствуют исходный генератор, metadata и построчный аудит, поэтому воспроизводится обучение по CSV, а не происхождение каждой синтетической записи. Данные читаются строками с обработкой пробелов перед CSV-кавычками; исходный файл не изменяется.
